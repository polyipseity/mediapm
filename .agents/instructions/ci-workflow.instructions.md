# CI and validation workflow

## Validation gates

Local git hooks (via `prek.toml`) enforce quality at three stages:

- **pre-commit** (`git commit`): `check-case-conflict`, `check-executables-have-shebangs`, `check-illegal-windows-names`, `check-merge-conflict`, `check-shebang-scripts-are-executable`, `check-symlinks`, `destroyed-symlinks`, `detect-private-key`, `end-of-file-fixer`, `fix-byte-order-marker`, `name-tests-test`, `trailing-whitespace`, `rumdl-fmt`, and `fmt` (cargo fmt on changed `.rs`).
- **commit-msg**: `commitlint` (Conventional Commits via `@commitlint/config-conventional`), self-provisioned by the hook and CI action — no repo `package.json`.
- **pre-push** (`git push`): `cargo-check --workspace --all-targets --all-features`, `clippy --workspace --all-targets --all-features`, `test` (`cargo run --package test-runner -- test --all-features --locked`: nextest plus the tempdir and janitor gates), and `test docs` (`cargo run --package test-runner -- doc --all-features --locked`: doctests plus the rustdoc link gate). Both test hooks are local hooks that call the `test-runner` crate, so the pre-push gate is the CI gate rather than an approximation of it — including the temp-directory gates, which pre-push did not run before the runner existed. The separate `rustdoc` hook id is gone; its work is the second half of `test docs`, so `SKIP=test-docs` is the handle for it.

Treat these as the canonical lint/format/check gate; use selective runs during development.

## CI parity

GitHub Actions (`.github/workflows/ci.yml`) mirrors the pre-push gate:

- The `Run tests` step is `cargo --locked test-all` and `Run doctests and rustdoc` is `cargo --locked test-doc-all`. Both are thin aliases over the `test-runner` crate, so the suite runs under `--all-features` — which already activates the opt-in `large-tests` feature (`mediapm-cas`), so there is no separate large-tests step and no `--large` flag. The runner's `test` subcommand runs nextest, then the unprefixed-tempdir gate, then the janitor dry-run gate; its `doc` subcommand runs the doctests, then the rustdoc link gate.
- The online demo YouTube regression (`online_sync_post_sync_dump`) is gated by the **3-level mechanism** (`example_isolation::ci_mode_detected()` skip + `MEDIAPM_RUN_ONLINE_SYNC=1` opt-in), not by feature selection. The two are orthogonal: `--all-features` activates `large-tests` and still does not run the YouTube test. This regression and the online demo keep the skip model because their subject is the real upstream; where an upstream can be mocked, prefer the two-path model instead (`example-execution-policy.instructions.md`, "A network-bound test gets two paths, not a skip ladder").
- `cargo clippy-all`, `cargo fmt-check`, `cargo build-all`.
- `cargo bin rumdl check` (project markdown lint).
- The `feature-matrix` job runs `cargo --locked run --package test-runner -- feature-matrix --locked`: one `cargo check` per crate per feature combination, with the combinations derived from `cargo metadata` by the runner rather than listed in YAML. A hand-maintained list is a list that silently rots when a crate gains a feature; the three gotchas the old inline list needed documented (`--no-default-features` for `mediapm-utils`, `required-features = ["cli"]` bin targets, and the deliberate absence of `--all-targets`) are properties of the derivation in `scripts/test-runner/src/matrix.rs`. `mediapm` declares the conductor's `tool-presets` feature unconditionally, because its config types, sync bridge, and workflow options use that surface in code no feature of its own gates; the declaration is what makes `cargo check -p mediapm --no-default-features` a build rather than a compile error, and it costs the stronger probe — that combination no longer exercises a provider-free `mediapm`.
- A `release` job builds `mediapm-cas`, `mediapm-conductor`, and `mediapm` with `--release`, as its own job so a slow release build does not delay the main one and a failure is attributable to the profile. Completion scripts are rendered by each package's build script, and the release profile is what a user runs: rendering used to be gated on that profile, so CI's debug build never exercised it and a broken CLI entry point went unnoticed for three months. The job covers the three packages whose build scripts render completions rather than the workspace, and it sets no skip flag — `MEDIAPM_SKIP_COMPLETION_BUILD` no longer exists, and a job that still skipped rendering would guard nothing. The contract itself is pinned by `src/mediapm/tests/int/completion_contract.rs`, which renders through the same `build_utils` entry point the build scripts call and compares the result against each CLI's declared `completions` shape.
- A `windows` job (windows-latest) runs `cargo --locked test-pkg mediapm-tests` (root script-test crate): the janitor tests (`tests/scripts/test-clean-mediapm-temp.{sh,ps1}` and the dry-run/real-run drivers around them), plus `cargo --locked test-pkg test-runner`, which runs `test-runner`'s unit tests under nextest and so exercises the temp-directory gate tests on Windows. It also runs `cargo --locked check -p mediapm-cas -p mediapm-conductor -p mediapm`, which executes those packages' build scripts — the ones that render completion scripts — and compiles their libs and bins, so completion generation is exercised on Windows, plus `cargo --locked check -p mediapm-cas --all-features --lib --bins --examples --test mod`, which reaches the CAS integration test target. That second step narrows targets but not features: it keeps `--all-features`, so it compiles the same modules every other gate does, including the ones `large-tests` unlocks. It is scoped rather than `--all-targets` because one target still does not compile on Windows on a stable toolchain: `is_same_file` in `src/mediapm-cas/src/storage/blob_store/fs.rs` compares `volume_serial_number` and `file_index`, behind the unstable `windows_by_handle` feature, so the lib's own unit tests fail to build there. `--all-targets` becomes usable once that comparison is expressed on stable Windows APIs. The two other packages cannot be cross-checked from macOS at all: `ring`'s C sources fail before the crate under test compiles, so `mediapm-cas` is the only package whose Windows compile is observable outside CI. pwsh is preinstalled; bash tests run via Git Bash `bash` probe and skip if absent. The doctest/rustdoc gate (`cargo test-doc-all`) is not part of the job and is still not exercised on Windows — nextest runs no doctests. No full-suite parity and no extra gates.

CI triggers on PRs and pushes to any branch, with concurrency deduplication (latest run per PR/commit).

## Explicit forms

When cargo aliases are unavailable:

- `cargo test -p <crate> --all-targets --all-features` = `cargo test-pkg <crate>`
- `cargo clippy -p <crate> --all-targets --all-features` = `cargo clippy-pkg <crate>`

The seam-dependent tests need the `test-seams` feature: a bare `cargo test -p mediapm` compiles the provider base-URL seams out, and `tests/int/mod.rs` refuses to build, so the mistake fails at the compiler rather than reaching the real upstream hosts. Every gate passes `--all-features` (see `example-execution-policy.instructions.md`, "Seams").

## Hook management

Install/update: `pre-commit install`. Run all: `pre-commit run --all-files`. One hook: `pre-commit run <hook-name>` (`test` for the suite plus its gates, `test-docs` for doctests plus rustdoc). Skip: `SKIP=test git commit -m "msg"` / `SKIP=test-docs git commit -m "msg"`. There is no `rustdoc` hook id to skip; `SKIP=rustdoc` matches nothing.

## Hook failure recovery

- `fmt` (rustfmt) and `rumdl-fmt` auto-fix changed files and **fail the commit** when a fix was applied (exit 1, "files were modified by this hook"). Recovery: verify HEAD unmoved (`git rev-parse HEAD`), `git add` the modified files, retry with a fresh `git commit` — never `--amend`.
- `rumdl-fmt` enforces list indentation (MD007/MD032) and flattens nested lists. Restore hierarchy with 3-space bullets and 5-space sub-bullets (the `commit-staged.prompt.md` style, which the hook leaves untouched).
- prek stashes unstaged changes to `~/.cache/prek/patches/*.patch` around each hook and restores them after, so working-tree state is preserved.

## Known nextest caveats

1. **No doctest support.** Pair nextest with `cargo test --doc --workspace` (why `cargo test-all` and pre-push's `test-docs` hook are a second command rather than one).
2. **Example `main()` is not executed.** Nextest compiles examples and runs embedded `#[cfg(test)]` modules with `--all-targets` but never runs an example's `main()`; that is the embedded tests' job (see `example-execution-policy.instructions.md`).
3. **`#[should_panic]` tests may timeout.** Nextest applies a per-test timeout (`slow-timeout` in `.config/nextest.toml`); a deadlocking `#[should_panic]` is killed by the timeout. Adjust `slow-timeout` if needed.
4. **Leak detection reports a test whose capture pipe was still open, not a test that leaked.** Nextest waits `leak-timeout` (100 ms) after a test process exits and checks whether its stdout/stderr reached EOF, so the holder is any process that inherited the write end, which is why a `LEAK` line can land on a test that spawns nothing at all. cargo-nextest 0.9.140 had exactly that failure mode on macOS: without atomic `CLOEXEC` a concurrently spawned test inherits a sibling's capture pipe, and the sibling is then blamed at random (`rust-lang/rust#95584`, fixed upstream by a process-spawn lock in `nextest-rs/nextest#3553`). The pin in `Cargo.toml`'s `[workspace.metadata.bin]` is 0.9.146 for that reason, and nothing in this repository leaves a process un-reaped, so treat a `LEAK` line as a real finding again. Do not tune it away: raising `leak-timeout` hides real leaks, `result = "fail"` turns a known false positive red, and a per-test override cannot work because the victim of the race is random, so a filter would have to be suite-wide.
5. **No `--nocapture` by default.** Use `cargo nextest run --show-output` for live output; `test-all` does not pass it.
6. **Network-heavy tests are serialized with a long timeout.** The `mediapm_demo_online` example tests and `all_platform`'s `#[ignore]`d real-upstream twin each download the full managed-tool set (ffmpeg ~163M) into a fresh empty cache; parallel runs saturate bandwidth and trip the default slow-timeout. `all_platform`'s hermetic test downloads nothing — it answers a mock upstream — and stays in the group only because the filter matches that module's test names. The offline `mediapm_demo` downloads nothing, so it is in the group only to stay serialized with its network-using siblings. They use `[test-groups] network = { max-threads = 1 }` with `slow-timeout = { period = "60s", terminate-after = 600 }` in both `default` and `ci` profiles; filter is `binary(mediapm_demo) or binary(mediapm_demo_online) or test(all_platform)` (`binary()` exact-matches example binary names, `test()` contains-matches integration tests — see `.config/nextest.toml`). Fast non-network tests in those binaries join the group. Do not remove this override without fixing the download-contention flake. `terminate-after = 600` must equal `DEMO_ONLINE_HARD_TIMEOUT_TOTAL_SECS` in `src/mediapm/examples/mediapm_demo_online.rs` — update both together. YouTube intermittently returns HTTP 403 to yt-dlp ("No supported JavaScript runtime" — EJS deprecation), a transient anti-bot flake, not a code regression — re-run the failing demo test in isolation to confirm.
