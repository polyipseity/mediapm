# Progress Terminal/Screen Completion Implementation Plan (rev 25)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the one-terminal-per-sync progress architecture reachable at runtime, collapse the duplicated screen types, restore commit-on-join, and clear every gate that currently blocks the pre-push hook.

**Architecture:** `ProgressTerminal` is the single owner of the `MultiProgress`, `WriteGate`, ticker, debug sink and pre-roll; it is created once per sync and the three phase screens (tool-sync, workflow, materialization) are derived from it and joined before the next begins. Each screen's `ProgressRenderer` draws through the *terminal's* draw target, and the terminal holds the only strong reference to the renderer, so `join()` can release it — dropping the renderer drops its `ProgressBar`s, which is what makes indicatif keep their lines as committed scrollback. **A commit has two halves and both are required:** the frame is **retained** (`LineAdjust::Keep`, deliberately not a clear) **and** the cursor is **advanced one row past it** — a single CR+LF issued by `WriteGate::commit_frame()` at the end of `ProgressRenderer::finalize()`, inside the open write window (`inner/gate.rs`, `inner/renderer.rs`; landed as `bb537ecd`). Retention alone is nominal, not real: the draw protocol leaves the cursor resting on the frame's last row, so the frame is still the live region and the next screen's band claims and clears it. The advance is what makes "committed to scrollback" true for the terminal rather than nominal.

**Tech Stack:** Rust 2021, `indicatif` 0.17.11 (`MultiProgress`, `ProgressBar`, `BarState::mark_zombie`, `LineAdjust`), `console` 0.15, `tokio`, `cargo-nextest`. Crates touched: `mediapm-utils` (owns progress), `mediapm`, `mediapm-cas`.

## Verified facts

Everything in this section was **measured** on the working tree, not inferred from reading `indicatif`. Reproduce with a temporary `TermLike` wrapper that logs every call, delegating to an `InMemoryTerm`.

### Corrected retention model (per configuration)

Retention depends on the **configuration**, and the two configurations retain for different reasons. **Any other statement in this plan that attributes retention on the production path to the finish policy is superseded by this subsection.**

**Write-gated targets (production).** `BufferedTerm` suppresses every write outside an open `WriteWindow` (`src/mediapm-utils/src/progress/inner/gate.rs:47-110`), and the only windows are `run_frame` step 6, `attach`, and `finalize`. The drop-time `BarState::drop` → `finish_using_style` → `draw` fires **after** `finalize`'s guard closes the window, so its clear never reaches the terminal. **The write gate is what retains the line** — verified by measurement: the terminal op stream and `InMemoryTerm::contents()` are byte-identical on the gated path across `bfa740bc` and `960fdc60`.

**Ungated targets (tests).** Retention comes from `with_slot_finish_policy` applying `ProgressFinish::AndLeave`. It is **defense-in-depth** — it prevents retention from implicitly depending on gate window timing — and it is **inert in production**. Without it, indicatif's default `AndClear` would clear an unfinished bar's line in `BarState::drop`.

**`AndLeave` cannot affect finished bars.** `indicatif-0.17.11/src/state.rs:222-225` returns before `finish_using_style` at `:227`, and the policy is read only inside it. The change is narrow.

The pre-existing integration tests used a **no-op** gate (`with_multi_progress`), which is why their red/green power came from the ungated configuration and why they do not pin production behaviour.

`join` has **never** waited for bars to finish: at `61bdbdf9` the old `inner/group.rs:379` was literally `pub fn join(&self) {}`. Several docs wrongly claim otherwise; that is pre-existing drift, not fallout from this work.

### Pre-roll sizes itself from the dimension source (F14)

The pre-fix `ProgressRenderer::pre_roll_if_needed` was:

```rust
let rows = self.dim_source.dimensions().0 as usize;
let _ = term.move_cursor_down(rows);
for _ in 0..rows { let _ = term.write_line(""); }
let _ = term.move_cursor_up(rows);
```

The cursor round-trip is load-bearing: it guarantees the `rows` blank lines scroll the terminal even when the cursor starts at the top, which is exactly what `pre_roll_with_existing_content_scrolls_it_away` asserts. Rev 2's replacement used `term.height()` with bare `write_line` calls and no cursor moves; it would have failed six tests.

### Verified indicatif mechanics the plan relies on

Read from `indicatif-0.17.11`:

- `ProgressBar::drop` → `BarState::drop` → `ProgressDrawTarget::mark_zombie` → `MultiState::mark_zombie`. When the dropped member is at the head of `ordering` **and nothing live precedes it**, it is reaped immediately with `adjust_last_line_count(LineAdjust::Keep(count))` **and** `remove_idx` (which returns the index to `free_set`); `Keep` *subtracts* from `last_line_count` (`draw_target.rs:313`), so the next draw does not clear those lines. That eager head path is the only route that both retains lines and frees the slot inside `drop`; F28 states its condition and the three ways retention is destroyed.
- Non-head members are only flagged `is_zombie` and reaped lazily, by the next successful draw's reap loop, which `break`s at the first non-zombie (`multi.rs:289-297`) — and a deferred zombie stays in `ordering` and is re-drawn by every draw, so its lines accumulate at the top of the line list. Committing dependably therefore requires dropping bars in slot order (head first) with nothing live ahead of them in `ordering`; `Vec<RenderedSlot>` drops index 0 first, which matches `ordering.first()` whenever no earlier slot is still live.
- `MultiProgress::remove(&bar)` asserts `Arc::ptr_eq` against its own state, so a bar must be removed through the same `MultiProgress` it was added to.
- `WriteGate` is `#[derive(Debug, Clone)]` with `flag: Arc<AtomicBool>`, and `open` / `suppress` / `is_suppressed` are `pub(crate)` — so a sibling module can clone and drive it, and no signature change is needed to share it.

//! the debug sink must stay wired, and pre-roll must fire exactly once per
//! terminal regardless of how many screens are created.

use std::io::Write;
use std::sync::{Arc, Mutex};

use indicatif::{InMemoryTerm, MultiProgress, ProgressDrawTarget};

use super::super::{
    DimensionSource, ProgressDebugSink, ProgressTerminal, TestDimensionSource,

/// Terminal dimensions used by every test in this module.  `capacity` is
/// pinned to the same value: `InMemoryTerm::contents()` only reflects frames
/// drawn at or above the terminal's own height, so a larger capacity makes
/// every assertion below read `""` even though the frame was drawn.
const ROWS: u16 = 10;
const COLS: u16 = 80;

/// A `Write` sink that keeps everything written to it, so a test can read the
/// JSONL frames a debug sink emitted.
#[derive(Clone, Default)]
struct SharedVec(Arc<Mutex<Vec<u8>>>);

impl SharedVec {
    /// Return everything written so far as UTF-8 lossily decoded text.
    fn as_string(&self) -> String {
        let bytes = self.0.lock().expect("capture lock").clone();
        String::from_utf8_lossy(&bytes).into_owned()
    }
}

impl Write for SharedVec {
    fn write(&mut self, buf: &[u8]) -> std::io::Result<usize> {
        self.0.lock().expect("capture lock").extend_from_slice(buf);
        Ok(buf.len())
    }

    fn flush(&mut self) -> std::io::Result<()> {
        Ok(())
    }
}

///
/// The dimension source and the slot capacity are both pinned to the
/// `InMemoryTerm` size, so `contents()` observes every drawn frame.

    let target = ProgressDrawTarget::term_like(Box::new(term.clone()));
    let dims = Arc::new(TestDimensionSource::new((ROWS, COLS)));
    ProgressTerminal::builder()
        .with_multi_progress(MultiProgress::with_draw_target(target))
        .with_dim_source(dims as Arc<dyn DimensionSource>)
        .capacity(ROWS as usize)
        .with_ticker_enabled(false)
        .build()
}

    let terminal = terminal_with_term(&term);
    let screen = terminal.screen().build();

    bar.advance(1);

/// released slots let the second screen render in full at `capacity == ROWS`.

/// This is the release half only.  The committed frame cannot stay inside

fn sequential_screens_share_one_draw_target() {

    let second = terminal.screen().build();

```rust
/// Create the one live [`ManagedScreen`] on this terminal.
///
/// The renderer draws through the terminal's single [`MultiProgress`] and
/// honours the terminal's [`WriteGate`], so every screen of a sync renders
/// into the same draw target and frames are buffered as a unit.
///
/// # Panics
///
/// Panics when a screen is already live on this terminal: two live screens
/// would mean two renderers driving one `MultiProgress`.
fn build_screen(terminal: &ProgressTerminal, overall: Option<(String, u64)>) -> ManagedScreen {
    let mut state = terminal.inner.state.lock().unwrap_or_else(std::sync::PoisonError::into_inner);
    if state.screen.is_some() {
        panic!(
            "ProgressTerminal already has a live screen; \
             join() or drop the current screen before creating a new one"
        );
    }
    let id = ScreenId(state.next_id);
    state.next_id += 1;

    // One pre-roll per terminal, before any bar of the first screen draws:
    // the bars must appear below the scrolled content, not over it.
    terminal.inner.pre_roll_if_needed();

    let mut renderer = ProgressRenderer::from_mp(
        terminal.inner.mp.clone(),
        terminal.capacity,
        Arc::clone(&terminal.inner.dim_source),
        terminal.inner.gate.clone(),
        Arc::clone(&terminal.inner.time_source),
        terminal.inner.debug_sink.clone(),
    );
    renderer.dynamic_height = terminal.dynamic_height;
    if let Some((label, total)) = overall {
        renderer.add_overall(&label, total);
    }
    let renderer = Arc::new(Mutex::new(renderer));

    // A live screen owns the terminal's ticker; the previous one is gone.
    state.ticker.take();
    state.renderer = Some(Arc::clone(&renderer));
    state.ticker =
        if terminal.ticker_enabled { spawn_ticker(Arc::downgrade(&renderer)) } else { None };
    state.screen = Some(ScreenState { id });
    drop(state);

    ManagedScreen {
        inner: Some(Arc::clone(&terminal.inner)),
        renderer: Some(renderer),
        screen_id: id,
        joined: std::sync::atomic::AtomicBool::new(false),
    }
}
```

The two near-identical `if let Some(...) / else` branches collapse into one because `add_overall` is available in both cases.

    ///
    /// Pre-roll emits one blank line per terminal row so existing terminal
    /// content scrolls into scrollback before the first bar draws, instead of
    /// being overwritten.  It belongs to the terminal rather than a screen: a

    /// A `None` `pre_roll_term` (a caller supplied a bare [`MultiProgress`])
    /// makes this a no-op.  The one-shot flag is consumed either way.

        let Some(ref term) = self.pre_roll_term else { return };
        let rows = self.dim_source.dimensions().0 as usize;
        let _ = term.move_cursor_down(rows);
        for _ in 0..rows {
            let _ = term.write_line("");
        }
        let _ = term.move_cursor_up(rows);
    }
}

**The `Vec`-order claim is conditional, and the condition is what makes it work (F28).** Dropping in `Vec` order reaches the head of `ordering` first **only while nothing live precedes the retired slots**. `MultiState::mark_zombie` (`multi.rs:239-266`) branches on `if index != self.ordering.first().copied().unwrap()` (`:244-246`): the **head** bar gets `adjust_last_line_count(LineAdjust::Keep(n))` **and** `remove_idx` (`:265`, pushing its index into `free_set` at `:455`) — eagerly, inside `drop` — while **any other** bar is only marked `member.is_zombie = true` (`:247-248`) and returns, with no `Keep` and no `free_set` push. ///
/// The screen holds a `Weak` reference to its renderer because the terminal's
/// `TerminalState.renderer` owns it strongly; [`join`](Self::join) releases
/// that owner and thereby drops every `ProgressBar` in the screen, which

/// the commit: the cursor also has to be moved past the frame, which the

pub struct ManagedScreen {

    ///
    /// Renders the final frame, clears the terminal's live-screen slot and
    /// releases the terminal's strong reference to the per-screen renderer.
    /// That drop cascades to every `ProgressBar` the screen reserved, which
    /// retains their lines: indicatif reaps a dropped bar as a zombie and keeps
    /// its drawn lines, while returning the bar's slot index to the
    /// `MultiProgress` free set for the next screen.  Retaining the lines is
    /// only half of the commit — the renderer's finalize path then advances the
    /// cursor one row past the frame (`WriteGate::commit_frame`), because a
    /// frame the cursor still rests on is the live region, not scrollback; see
    /// the module docs in `inner/gate.rs`.
    ///
    /// Two limits of that retention, both measured on the terminal path (F30):
    ///
    /// - Only a bar that is **finished** at this point keeps its line.
    ///   indicatif's `BarState::drop` short-circuits for a finished bar and
    ///   keeps its lines, but an unfinished bar is dropped through the default
    ///   `ProgressFinish::AndClear`, which hides it.  Commit a screen only
    ///   after finishing its bars, or those lines are cleared rather than kept.
    /// - The ticker's `Weak::upgrade()` fails here, but a tick already in
    ///   flight holds a strong clone of the renderer until it returns, so the
    ///   retired reservation can outlive `join` by up to one tick.
    ///   `ProgressRenderer::run_frame` returns immediately once finalized, so
    ///   that window is a single no-op tick and the reservation is dropped when
    ///   it ends; a screen built and drawn inside the window sees the retired
    ///   reservation for one frame.  `release_holds_with_the_ticker_running`
    ///   (Step 4) measures this window and cannot force a join into it.
    ///
    /// Idempotent: joining an already-joined (or never-live) screen is a
    /// no-op, which is what makes `Drop` safe to route through here.
    ///
    /// The terminal's state mutex is used unpoisoned: a poisoned lock is
    /// recovered with `PoisonError::into_inner` instead of being propagated,
    /// so this method has no panic path.
    pub fn join(&self) {
        if self.joined.swap(true, std::sync::atomic::Ordering::AcqRel) {
            return;
        }
        let Some(ref inner) = self.inner else { return };
        let mut state = inner.state.lock().unwrap_or_else(std::sync::PoisonError::into_inner);
        if !state.screen.as_ref().is_some_and(|s| s.id == self.screen_id) {
            return; // another screen is live; this one was already retired
        }
        if let Some(ref renderer) = state.renderer {
            renderer.lock().unwrap_or_else(std::sync::PoisonError::into_inner).finalize();
        }
        // Dropping the terminal's `Arc` drops the renderer, its slots and
        // therefore its bars.  The screen's own `Weak` does not keep it alive.
        state.renderer = None;
        state.screen = None;
        state.ticker.take();
    }

        total: u64,
        label: &str,
        style: BarStyle,
    ) -> ProgressBarHandle {

        // silently return a disabled handle.
        if !self.is_live() {
            panic!(
                "ManagedScreen is not the live screen \
                 (already joined or dropped)"
            );
        }
        let Some(ref weak) = self.renderer else {
            return ProgressBarHandle::disabled();
        };
        let Some(renderer) = weak.upgrade() else {
            return ProgressBarHandle::disabled();
        };
        let state;
        {
            let mut locked = renderer.lock().unwrap_or_else(std::sync::PoisonError::into_inner);
            state = Arc::new(SharedState::with_time_source_and_style(
                total,
                label,
                style,
                Arc::clone(&locked.time_source),
            ));
            locked.attach(&state);
        }
        ProgressBarHandle { state }
    }

**Acceptance criterion (F18, tightened by F26, restated by F29, landed as a three-test split).** After a screen joins, the next screen's frame on the same terminal MUST be **complete** at `capacity == terminal height` — its bar present and its frame at the expected height, not clipped. It must NOT assert that the joined screen's final frame is still in `contents()`: the eager `Keep` frees nothing on screen, the next frame is drawn one row below the committed row, and `InMemoryTerm` has zero scrollback, so the committed row is scrolled out of the harness's view (F29). Retention needs its own test at one row less than full capacity, and that test is **not** the release proof: at `capacity == ROWS - 1` it is green even before the fix (measured), because a one-bar leak fits exactly and the leaked bound member is redrawn at the head of the second screen's frame with byte-identical content, so the two states produce the same `contents()` at that capacity; it discriminates erasure, not leaking. Two distinct mechanisms are still in play and neither suffices alone: dropping the screen's bars (`BarState::drop` → `mark_zombie` → reap with `LineAdjust::Keep`) **retains** the drawn lines, while `MultiProgress::remove` — what the recovered `commit_bars()` used — **frees the slot index but erases the frame on the next draw** (`multi.rs:144-163`, `draw_target.rs:505-517`). The deliverable remains a determination, from the indicatif source, of which mechanism (or which ordering of the two) yields **both** retention and slot release, together with a proof of each where each is observable. `finalize()` alone gives neither: it keeps the joined screen's bars in the multi-state. Without slot release, Task 5 ships a terminal where phases 2 and 3 are invisible: each screen reserves `capacity` slots, and indicatif stops printing once the cumulative bar height exceeds the terminal height (`indicatif-0.17.11/src/draw_target.rs:545-552`), so a second screen at `capacity == ROWS` presents `1 + capacity` bars on a `rows`-tall terminal and draws nothing — measured: rows=40/capacity=40 → invisible, rows=40/capacity=10 → visible. Without retention, it ships a terminal that erases phase 1's committed output the moment phase 2 draws. **The contract has a third element, and the landed fix supplies it (rev 18).** Retention and slot release are necessary but not sufficient: with the cursor still resting on the frame's last row the committed frame is still the live region, so the next screen's band claims that row and the following in-place redraw clears it — "committed to scrollback" is nominal, not true, until the cursor moves past the frame. The landed fix adds exactly that half inside `ProgressRenderer::finalize()`: `WriteGate::commit_frame()` writes one CR+LF straight to the wrapped terminal through the gate's own handle while the write window is open. Read the requirement as **retain + advance**, and treat a `Keep`-only mechanism as incomplete (it was the pre-fix state, and the A/B run showed that newline alone, without the gate's failure reporting, still erased the frame).

**The proof is a split across three tests, and each states its own capacity.** (1) **Release** — `second_screen_renders_at_full_capacity` (below) builds screen 1, joins it, then builds screen 2 on the **same** terminal at `capacity == ROWS`, precisely the configuration that fails today, and asserts the second screen's frame only: its bar reached the terminal and its frame is at the expected height (rendered content, not merely non-empty output).     use indicatif::{InMemoryTerm, MultiProgress, ProgressDrawTarget};

    /// so `contents()` observes every drawn frame.
    const ROWS: u16 = 24;
    /// Terminal width used by the injected terminal.
    const COLS: u16 = 80;

    /// A `Write` sink that keeps everything written to it.
    #[derive(Clone, Default)]
    struct SharedVec(Arc<Mutex<Vec<u8>>>);

    impl std::io::Write for SharedVec {
        fn write(&mut self, buf: &[u8]) -> std::io::Result<usize> {
            self.0.lock().expect("capture lock").extend_from_slice(buf);
            Ok(buf.len())
        }
        fn flush(&mut self) -> std::io::Result<()> {
            Ok(())
        }
    }

    let root = mediapm_utils::temp::artifact_dir().expect("artifact dir");
    let cache_root = mediapm_utils::temp::cache_dir().expect("cache dir");
    let storage = MediaRuntimeStorage {
        cache_root_override: Some(cache_root.path().to_path_buf()),
        ..MediaRuntimeStorage::default()

    let term = InMemoryTerm::new(ROWS, COLS);
    let target = ProgressDrawTarget::term_like(Box::new(term.clone()));

        .with_dim_source(dims as Arc<dyn DimensionSource>)
        .with_progress_debug_sink(ProgressDebugSink::new(Box::new(capture.clone())))

        .with_ticker_enabled(false)
        .build();

        .await
        .expect("service");

        .sync_library_with_progress_overrides(SyncOptions::default(), overrides)
        .await
